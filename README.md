# AR 眼镜端软件 发行说明

**项目**：面向复杂火场的 AR 眼镜与负压爬壁车协同系统（星火天巡 / 南京师范大学）
**模块**：单兵智能穿戴端（AR 眼镜）上位机软件
**版本**：v1.3.0
**发布日期**：2026-07-06
**运行平台**：瑞芯微 RK3588（Ubuntu 20.04/22.04、Debian 11/12），单目 AR 眼镜 + MicroOLED

---

## 一、版本概要

v1.3.0 是 AR 眼镜端的**协同联调版本**。相对于上一版（v1.2.x，目录 `ar（优化版）`），本版把重心从"单机功能演示"转向"与负压爬壁车的端到端协同"：新增远程控制与远程串流两大模块，目标检测正式接入 UI 主链路，顶部状态栏引入安全系数指示，并补齐了 RK3588 平台的部署脚本、依赖清单与环境说明。

本版同时修复了三处会直接影响实机运行的问题：启动脚本无法调用主程序、中文字体在 Linux 上回退失败、手势线程退出时未回收摄像头资源。

## 二、新增功能

### 2.1 远程控制模块（RemoteCtrlWidget）

面向爬壁车的实时操控面板，替代此前的灯具/风扇演示控件。

- **连接状态管理**：独立连接按钮与状态指示灯（未连接 / 已连接），未连接时发送指令会给出明确错误提示而非静默失败。
- **速度调节**：0–100% 无级调速，默认值 50%，调速结果随指令一同下发。
- **五向运动指令**：`forward` / `backward` / `left` / `right` / `stop`，状态栏实时回显中文状态（前进中、后退中、左转中、右转中、已停止）及当前速度。
- **连续控制模式**：捏合手势按住时以 100 ms 周期持续下发方向指令，松开即发 `stop`，避免丢帧导致的车体失控。
- **第一视角视频回显**：控制界面内嵌 640×480 视频窗口，可独立启停视频流，操控时不必在窗口间切换。

### 2.2 远程串流模块（RemoteCameraWidget）

- 支持 HTTP-MJPEG 与 RTSP 两种拉流地址，界面可直接输入并切换，默认地址 `http://192.168.1.9:8080/video`。
- 串流画面之上叠加车体遥测面板：电量、温度、湿度实时数值。
- 告警项分区显示：前方障碍物、总延迟、连接状态，异常项自动高亮。
- 串流画面可按需叠加 YOLOv5 人体检测结果，实现"边看边检"。

### 2.3 目标检测模块接入主链路（ObjectDetectionWidget）

- 主菜单新增"目标检测"入口，与文字识别、语音识别、远程控制、远程串流并列。
- 基于 RKNN 加速的 YOLOv5，聚焦**人体目标**检测，用于浓烟环境下快速锁定被困人员。
- 采用 `showEvent` / `hideEvent` 生命周期自动启停，离开页面即释放推理资源，不再空转占用 NPU。
- 进入/退出时通过 `od_need_signal` 通知手势线程按需送帧，避免无用的图像传输开销。

### 2.4 顶部状态栏与安全系数指示

- 新增常驻状态栏，盾形图标 + 安全系数百分比，按阈值变色：≥80% 绿色、50–79% 橙色、<50% 红色。
- 2 秒周期刷新，为消防员提供持续的态势感知参考。

### 2.5 RK3588 部署配套

- 新增 `start_rk3588.py`：启动前自动检测平台型号、Python 版本与关键依赖，并尝试将 CPU 切至 performance 模式、关闭屏幕保护。
- 新增 `requirements.txt`：锁定 PyQt6、OpenCV、NumPy、rknn-toolkit2 等依赖及最低版本。
- 新增 `README_RK3588.md`：覆盖系统依赖安装、RKNN 模型部署、性能调优、摄像头/蓝牙故障排查。

## 三、变更与改进

| 项目 | v1.2.x | v1.3.0 |
|---|---|---|
| 主菜单功能数 | 3 项 | 5 项（新增远程控制、目标检测） |
| 远程控制 | 无（仅有灯/风扇演示控件） | 完整控制面板 + 连续手势控制 |
| 车体遥测 | 无 | 电量/温湿度 + 三项告警联动 |
| 视频流地址 | 固定 | 界面可配置，支持 HTTP / RTSP |
| 目标检测 | 未接入主菜单 | 正式入口 + 生命周期自动管理 |
| 状态显示 | 无 | 顶部安全系数状态栏 |
| 部署配套 | 无 | 启动脚本 + 依赖清单 + 部署文档 |

其他改进：

- 图像送帧改为**按需分发**：手势线程根据当前页面标志位决定是否推送帧，避免多页面同时接收造成重复解码。
- 手势线程增加卡尔曼滤波平滑（沿用 v1.2.x）并保留镜像翻转修正，佩戴手套场景下配合二次确认策略降低误触发。
- OCR 结果绘制改在文本框内部完成，标注不再相互压盖。

## 四、缺陷修复

**1. 启动脚本无法启动主程序（严重）**
`start_rk3588.py` 调用 `main.main()`，但 `main.py` 中不存在该函数，脚本必然抛出 `AttributeError` 并退出。已将其内部逻辑封装为 `main()` 函数，并补回 `if __name__ == "__main__"` 入口，两种启动方式现均可用。

**2. 中文字体在 Linux 上回退失败**
OCR 结果绘制的字体候选列表被改为仅含 Windows 路径（`C:/Windows/Fonts/...`），在 RK3588 的 Ubuntu/Debian 上全部失效，中文标注会退化为方块。已恢复 Linux 字体路径（`wqy-zenhei.ttc`、`NotoSansCJK-Regular.ttc`）并置于 Windows 路径之前，两端均可正常渲染。

**3. 手势线程退出时未释放资源**
原 `main.py` 在 `sys.exit(app.exec())` 之后才调用 `gesture_thread.stop()`，该行永不执行，导致退出时摄像头句柄与 MediaPipe Hands 实例泄漏。已改为先取回退出码、再 `stop()` 并 `wait()`，最后返回退出码。

## 五、已知问题与限制

以下为**本版未解决**的问题，使用时请注意：

1. **机器人控制指令未真正下发。** `MainWindow.handle_robot_control()` 目前仅有日志打印，没有实际通信代码（`widget_main.py:2264`）。界面上的连接状态为本地模拟，不会建立真实的蓝牙/串口链路。`requirements.txt` 中的 `pybluez` 亦未被任何模块引用。
2. **手势方向识别为随机模拟。** `detect_gesture()` 使用 `random.random()` 产生方向结果（`widget_main.py` 约 886 行），仅供演示，不可用于实际控制。
3. **安全系数为模拟数据。** `simulate_safety_factor()` 由 2 秒定时器驱动生成，尚未接入真实传感器。
4. **语音识别模块已停用。** `SpeechRegWidget` 的识别线程代码整体注释，页面仅保留 UI 骨架，进入后无实际功能。
5. **部分依赖未被使用。** `python-docx`、`requests`、`psutil` 在代码中无引用，可从 `requirements.txt` 中移除以精简部署体积。
6. **依赖体积偏大。** `rknn-toolkit2` 为必需项但安装耗时较长，建议在板端预先完成安装。
7. **手势交互在佩戴厚重消防手套时识别率下降**，关键指令需依赖二次确认机制。

## 六、安装与运行

```bash
# 1. 系统依赖
sudo apt update && sudo apt install -y python3 python3-pip python3-dev build-essential
sudo apt install -y libopencv-dev python3-opencv libqt6core6 libqt6gui6 libqt6widgets6

# 2. Python 依赖
pip3 install -r requirements.txt

# 3. 确认 RKNN 模型就位
ls neural_net/rknn/yolov5/model/     # 应含 yolov5_rknn7.0_best.rknn、anchors_yolov5.txt

# 4. 启动（推荐）
chmod +x start_rk3588.py && ./start_rk3588.py

# 或直接启动
python3 main.py
```

摄像头权限问题请将当前用户加入 `video` 组：`sudo usermod -aG video $USER`。
